# Shrinking and reduction budgets

`HierarchicalShrinker` evaluates candidates sequentially and accepts only a case
that is smaller, domain-valid, and reproduces the exact target
`FailureSignature`. It uses canonical case-digest caching and deterministic
candidate ordering.

The completed-run guarantee is deliberately local: no smaller valid,
same-signature candidate was found among candidates generated by the configured
reducers within the configured budgets. The testkit does not search the complete
possible case space and does not claim global minimality. The report stop reason
is `locally_minimal`, and its `guarantee` field is
`locally_minimal_under_configured_reducers`.

Composable reducers cover:

1. top-level world collections;
2. list records through partition-based ddmin;
3. mapping keys;
4. fault schedule partitions;
5. fault occurrences toward the first call;
6. optional actor attributes;
7. optional goal fields;
8. domain operation arguments through `ArgumentReducer`.

Configure bounded work:

```python
shrinker = HierarchicalShrinker(
    max_evaluations=250,
    max_elapsed_ms=10_000,
    confirm_signature_runs=2,
)
```

The default confirmation count is one for inexpensive deterministic tests.
Multiple runs can detect stochastic baselines. An inconsistent baseline stops as
`unstable_baseline`; the report retains observed signatures and traces and makes
no minimality claim.

Every report includes full initial/final case digests, size metrics, participating
reducers, the named validity predicate, target signature, candidate evaluations,
cache hits, invalid and different failures, accepted steps, elapsed time,
evaluation/time budgets, explicit budget-exhaustion flags, guarantee, and a typed
stop reason. Budget exhaustion returns the reduced case accepted so far and sets
`guarantee` to `budget_limited_reduction`; it makes no local-minimality claim.
